## Prompt Log Format

Explore (re-read the task, the relevant docs, and the code) → state a short plan → implement → verify each acceptance criterion → commit. Once C7 exists, any change to prompts, thresholds, or models requires an eval run (eval-driven development).

All acceptance criteria checked; typecheck, lint, and tests pass; docs updated if a decision changed; TASKS.md updated (Status, Actual time, Deviation from plan); prompts.txt updated; committed.

## Commits
Conventional commits with the task ID, e.g. "feat(C3): three-way resolution at intake". Never mix tasks in one commit.

Key commands (dev, test, typecheck, lint, seed, record, eval); folder structure per ARCHITECTURE.md; Vitest for tests; all model calls go through the AiProvider abstraction with Zod-validated structured output; prompts versioned in /prompts, with the version stored on every ai_decisions row; no secrets in code (.env.example only); respect the Non-goals in PRODUCT.md.
